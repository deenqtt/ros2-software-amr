BAB 1Pengenalan Sistem

AMR Control adalah satu tempat untuk mengatur robot AMR (Autonomous Mobile Robot): mendaftarkan robot, membuat peta, menandai titik tujuan, menyusun rute, menjalankan mission, dan memantau hasilnya — untuk satu robot maupun satu armada.

1.1Komponen utama

DI BROWSER

Web UI

Aplikasi yang dibuka operator di browser komputer, tablet, atau HP. Semua pekerjaan dilakukan di sini, setelah login.

DI SERVER / RASPBERRY PI

Backend (registry)

Menyimpan semua data: akun, robot, peta beserta versinya, station, zone, mission, riwayat run, dan jejak aktivitas. Ini sumber kebenaran.

DI SETIAP ROBOT

Robot Agent

Program di komputer robot (Jetson). Mengambil tugas dari backend, menyalakan Nav2/SLAM, menjalankan mission, dan melaporkan progresnya.

DI LAYAR ROBOT

Kiosk

Layar untuk orang di sekitar robot: wajah robot, tujuan, dan tombol besar Sudah diambil saat pesanan tiba.

1.2Cara data mengalir

Hal terpenting: browser tidak memerintah robot untuk menjalankan mission. Browser hanya menyimpan "apa yang harus dikerjakan" ke backend; robot sendiri yang mengambil dan mengerjakannya. Karena itu menutup browser tidak menghentikan robot, dan robot tetap menyelesaikan mission walau server atau WiFi putus.

  • Browser → Server: semua data yang Anda buat disimpan ke backend, setelah Anda login.
  • Robot → Server: agent memeriksa backend setiap ±10 detik — peta apa, mode apa, ada mission? — lalu melaporkan progres.
  • Browser ↔ Robot (langsung): hanya untuk hal live: peta, laser, posisi robot, serta Set pose / Go here.
  • Agent ↔ Kiosk (di dalam robot): status pengantaran dan tombol konfirmasi — tetap jalan tanpa jaringan.

BAB 2Login, Akun & Hak Akses

Setiap orang memakai akunnya sendiri. Role akun menentukan apa yang boleh dilakukan, dan setiap perubahan tercatat atas namanya.

2.1Masuk

  1. Buka alamat Web UI di browser (mis. http://192.168.2.84), isi Username dan Password, klik Sign in.
  2. Bila akun baru dibuat oleh admin (password sementara), Anda langsung diminta membuat password sendiri sebelum bisa memakai aplikasi.
  3. Setelah itu Anda masuk ke halaman yang dituju, biasanya Dashboard.
  • Sesi berakhir setelah 12 jam tanpa aktivitas (satu shift). Anda akan diminta login lagi dan kembali ke halaman yang sama.
  • Setelah 5 kali salah password, login untuk akun itu dijeda 5 menit; layar menampilkan hitung mundurnya.
  • Bila server tidak terjangkau, halaman login memberi tahu bahwa masalahnya di jaringan, bukan di password.

2.2Super admin pertama

Server baru belum punya akun. Akun pertama — Super admin — dibuat dari file pengaturan server (AMR_BOOTSTRAP_USER dan AMR_BOOTSTRAP_PASSWORD, lihat Bab 10.1). Akun ini wajib mengganti password saat login pertama; setelah itu kedua baris pengaturan tersebut sebaiknya dihapus.

2.3Role & hak akses

Ada empat role berjenjang; setiap role mencakup hak role di bawahnya.

RoleBoleh
ViewerMelihat armada, peta, mission, dan riwayat. Tidak mengubah apa pun.
Operator+ menjalankan dan menghentikan mission, mengirim goal, mengemudikan dan memarkir robot.
Admin+ mengedit peta, station, zone, mission, dan daftar robot.
Super admin+ mengelola akun (Users) dan membaca jejak aktivitas (Activity).

Tombol yang tidak boleh dipakai tidak disembunyikan: tombol itu terkunci, dan saat disentuh muncul keterangan role yang dibutuhkan, mis. "Needs the operator role". Dengan begitu semua orang tahu fitur itu ada dan kepada siapa harus meminta.

Hak akses dijaga oleh server. Kunci di layar hanya memberi tahu lebih awal.

2.4Menu pengguna & ganti password

Klik nama Anda di kanan atas untuk melihat role, Change password, dan Sign out. Lupa password? Minta Super admin melakukan reset di halaman Users; Anda akan mendapat password sementara yang wajib diganti saat login.

BAB 4Alur Kerja dari Nol sampai Robot Jalan

Urutan pekerjaan untuk lokasi baru. Ikuti dari atas ke bawah; detail setiap layar ada di Bab 5, dan cara memasang server serta robot di Bab 10.

  1. Login sebagai Admin atau Super admin.
  2. Daftarkan robot. Robot → Add robot, isi nama dan alamat rosbridge (mis. ws://192.168.2.133:9090). Pasang Robot Agent dan Kiosk di robot dengan ID robot tersebut (Bab 10.2).
  3. Buat peta. Maps → Create map, pilih robot, kemudikan sampai seluruh area terpetakan, lalu Save map. Bila sudah punya file peta (.yaml + .pgm), gunakan Upload map.
  4. Tugaskan peta. Di Maps, klik Assign, centang robot, Apply. Robot memuat peta dalam ±10 detik.
  5. Mode kerja. Di Dashboard, bila robot Parked, klik Release; Nav2 menyala sendiri.
  6. Posisi awal. Buka navigasi robot → Set pose → tekan di posisi robot dan seret ke arah hadapnya.
  7. Station. Station → Add station → klik di peta. Atau kemudikan robot ke titik itu lalu Capture.
  8. (Opsional) Zone. Zone → pilih jenis → klik sudut-sudut area.
  9. Mission. Mission → New mission → klik station sesuai urutan → atur Wait for confirm di meja tujuan → Save.
  10. Jalankan & pantau. Run (atau dari navigasi: pilih rute → Start mission). Notifikasi muncul saat robot tiba dan saat mission selesai; di meja tujuan Kiosk menunggu tombol Sudah diambil.
Tidak perlu "start" setiap pagiRobot yang sudah punya peta dan mode Working menyalakan navigasinya sendiri saat dihidupkan.

5.2Robot — daftar robot

  • Robot name — nama yang tampil di mana-mana; samakan dengan tulisan di badan robot.
  • Bridge WebSocket — alamat rosbridge, mis. ws://192.168.2.133:9090.
  • ROS domain ID — opsional (0–232).

Details membuka halaman teknis robot; menu ⋯ berisi aksi lain seperti mengedit atau menghapus robot.

Menghapus robotHanya menghapus robot dari daftar. Peta, station, dan mission tidak ikut terhapus.

5.3Robot Navigation — halaman kerja satu robot

Halaman yang paling sering dipakai operator: peta live, posisi robot, mengirim goal, menjalankan mission, dan menghentikan robot.

Bagian atas

  • Nama robot, status koneksi, dan tab Navigation / Details.
  • Stop & park (merah) — membatalkan goal dan mission yang berjalan, lalu memarkir robot. Robot tetap diam sampai di-Release.
Bukan E-STOP fisikTombol ini menghentikan perintah perangkat lunak, bukan memutus daya motor. Untuk keadaan darurat gunakan tombol E-STOP di robot.

Panel Status & mission

BarisIsi

5.6Map Editor — merapikan peta

  • Alat: Brush (B), Line (L), Block (R), Fill (F), Pan (H).
  • Cat: Obstacle (dinding), Free (lantai), Unknown (belum terpetakan). Ukuran kuas 5 cm sampai 1 m ([ ]).
  • Pintasan: Spasi + seret = geser; tahan \ = lihat peta asli; Ctrl+Z undo; Ctrl+Shift+Z redo.
  • Save: isi What changed, lalu pilih Publish a new version (disarankan, bisa dikembalikan) atau Replace (menimpa, tidak bisa dikembalikan).

5.7Survey — membuat peta dengan mengemudikan robot

  1. Mulai — Start mapping. Robot keluar dari navigasi, mission berjalan dibatalkan, SLAM menyala.
  2. Kemudikan — joystick di layar (lepas = berhenti), atau gamepad dengan menahan tombol bahu (L1). Kecepatan Slow / Normal / Fast.
  3. Simpan — Save map dan beri nama. Peta disimpan ke robot, lalu dikirim ke daftar peta.

E-STOP di halaman ini langsung menghentikan robot dan SLAM. Stop mapping mematikan SLAM tanpa menyimpan.

5.8Mission — daftar rute dan yang sedang berjalan

  • Pilih peta di kanan atas; mission selalu milik satu peta.
  • Run — pilih robot (yang memakai peta ini) dan cara jalan: Once, Laps, Until stopped.
  • Edit — Mission Editor. ⋯ — hapus rute (riwayat run tetap disimpan).
  • Running now: Watch (buka navigasi robot), Stop after lap, Cancel.

BAB 7Robot Agent

Program yang berjalan di komputer setiap robot — penghubung antara apa yang Anda atur di Web UI dan apa yang benar-benar dikerjakan robot.

7.1Tugas agent

Mengatur mode

Menyalakan atau mematikan Nav2 (navigasi) dan SLAM (membuat peta) sesuai Working, Parked, Surveying.

Mengurus peta

Mengunduh peta yang ditugaskan, memeriksa keutuhannya, menyimpannya di robot, dan memuatnya ke Nav2.

Station & zone

Mengambil station dan zone peta aktif, menyimpannya di robot, dan meneruskan zone ke Nav2.

Mission & Kiosk

Mengirim robot ke setiap station, menunggu konfirmasi di meja tujuan, melaporkan progres, dan memberi tahu Kiosk.

7.2Siklus sinkronisasi (setiap ±10 detik)

  1. Baca registry — peta dan mode yang diminta.
  2. Kirim laporan tertunda — bila sebelumnya offline.
  3. Siapkan peta — unduh bila berubah, cek keutuhan, muat.
  4. Sesuaikan mode — nyalakan atau matikan Nav2/SLAM.
  5. Station & zone — simpan ke robot dan teruskan ke Nav2.
  6. Cek mission — ada run untuk robot ini? Jalankan.

Karena robot yang menarik data, robot tetap bekerja di belakang NAT atau saat berpindah access point WiFi. Konsekuensinya, perubahan di Web UI butuh hingga ±10 detik untuk sampai.

7.3Mode robot

Di Web UIYang terjadi
Working (Release)Nav2 dan peta aktif menyala; robot siap menerima goal dan mission. Kondisi normal.
Parked (Park / Stop)Nav2 dimatikan; robot diam dan tidak menerima mission.
SurveyingSLAM menyala untuk membuat peta.

7.4Menjalankan mission

  1. Ambil run beserta daftar step-nya dari server.
  2. Setiap step: kirim robot ke station. Selama berjalan agent memeriksa pembatalan setiap 2 detik dan memberi tahu Kiosk bila robot hampir sampai (±1,5 m) atau terhalang.
  3. Tiba: lapor "reached" (memicu notifikasi). Bila step bertanda Wait for confirm, robot menunggu tombol Sudah diambil di Kiosk, paling lama 2 menit, lalu lanjut sendiri. Setelah konfirmasi robot diam 3 detik agar orang sempat mundur dari nampan.
  4. Akhir: lapor done. Bila satu step gagal, run dihentikan dan dilaporkan failed beserta alasannya — tidak dicoba ulang otomatis.

7.5Saat server tidak terjangkau

SituasiPerilaku
Robot dinyalakan saat server matiMemakai catatan registry terakhir dan peta dari cache, hanya bila peta cache masih utuh. Station dan zone dibaca dari disk.
Jaringan putus di tengah missionMission dilanjutkan. Laporan disimpan dan dikirim berurutan saat server kembali.
Server masih mengira mission berjalanRobot ingat run yang sudah ia selesaikan — tidak menjalankan rute dua kali.
Operator membatalkan saat robot offlineRobot baru tahu setelah jaringan kembali. Untuk hal mendesak gunakan tombol stop di robot.

Cara memasang agent di robot ada di Bab 10.2.

BAB 8Operasi Banyak Robot

Satu Web UI dan satu server melayani seluruh armada, sementara setiap robot mengurus dirinya sendiri.

8.1Aturan dasar

HalAturan
Satu robot, satu agentSetiap robot menjalankan agent sendiri dengan ID robot unik dari Web UI.
Satu robot, satu rosbridgeSetiap robot didaftarkan dengan alamat rosbridge-nya sendiri.
ROS_DOMAIN_ID berbedaBeri setiap robot nomor berbeda (mis. 11, 12, 13) agar data ROS tidak tercampur.
Peta bersamaBanyak robot boleh memakai versi peta yang sama; station dan zone otomatis berlaku untuk semuanya.
Satu run per robotSatu robot menjalankan satu mission dalam satu waktu. Mission yang sama boleh dijalankan robot berbeda.

8.2Menambah robot ke armada

  1. Tim robot menyiapkan stack robot: ROS 2, Nav2, workspace, rosbridge di port 9090, dan ROS_DOMAIN_ID unik.
  2. Web UI: Robot → Add robot. Salin ID robot dari halaman Details.
  3. Pasang Agent + Kiosk ke robot dengan ID tersebut (Bab 10.2).
  4. Maps → Assign peta ke robot baru, lalu Set pose di halaman navigasinya.

8.3Batasan saat ini

Robot belum saling berkoordinasi

Setiap robot merencanakan jalurnya sendiri; robot lain hanya terlihat sebagai rintangan. Belum ada pengaturan lalu lintas atau antrean di lorong sempit.

  • Penugasan manual: operator memilih robot untuk setiap run.
  • Tanpa antrean: mission baru ditolak bila robot masih menjalankan mission lain.
  • Keamanan robot: agent dan rosbridge belum memakai login/token. Simpan robot di jaringan tertutup atau VPN.
Saran

Satu peta per area kerja untuk semua robot di area itu; zone Speed limit atau Avoid di lorong sempit dan persimpangan.

BAB 9Kiosk — Layar di Robot

Layar untuk orang di sekitar robot. Bisa dibaca dari 1–2 meter dalam 2 detik: teks besar, satu pesan per layar, dan warna yang langsung menunjukkan kondisi. Berjalan di robot itu sendiri, jadi tetap bekerja walau WiFi atau server putus.

9.1Wajah robot

Dua mata yang berkedip, melirik, dan berekspresi sesuai keadaan — fokus saat berjalan, senang saat tiba, cemas saat terhalang. Disentuh, robot tertawa. Status bar di atas menampilkan nama robot, status, koneksi, jam, dan baterai.

9.2Tiba di tujuan — layar konfirmasi

Layar terpenting. Saat robot tiba di step bertanda Wait for confirm: nama tujuan besar, satu tombol hijau, bunyi "ding-dong", dan kalimat "Pesanan untuk Meja 5 sudah tiba". Bila tidak ada yang menekan, 30 detik sebelum habis robot mengingatkan sekali lagi, dan setelah 2 menit robot lanjut sendiri.

9.3Kondisi khusus

Bila agent di robot belum terdengar, layar menampilkan "Sebentar ya, saya sedang menyiapkan sistem" — bukan wajah yang seolah siap.

9.4Menu staf, bahasa & suara

  • Menu staf tersembunyi dari tamu: tahan pojok kiri atas 1,2 detik, lalu masukkan PIN (diatur saat instalasi, Bab 10.2).
  • Lanjutkan sekarang — sama dengan menekan Sudah diambil.
  • Teks besar — memperbesar tulisan.
  • Info teknis — nama robot, koneksi agent, mode, misi, rute, baterai.

Bahasa: Indonesia dan Inggris. Suara: bunyi per kejadian dan kalimat; suara alami bila Piper terpasang, selain itu espeak-ng.

BAB 10Instalasi & Deploy

Dua bagian dipasang terpisah: Web UI di server, dan Agent + Kiosk di setiap robot. Stack robot sendiri (ROS 2, Nav2, workspace, rosbridge) disiapkan oleh tim robot.

10.2Robot Agent + Kiosk (setiap robot)

Script menyalin aplikasi ke robot, lalu — setiap langkah mengecek dulu dan hanya memasang yang belum ada:

  1. Mengecek stack robot (ROS 2, workspace, paket Nav2). Bila ada yang kurang, berhenti dengan daftarnya untuk tim robot — tidak memasang atau mengubah stack robot.
  2. Memasang kebutuhan Agent & Kiosk: tampilan layar penuh (cage), suara (espeak-ng), dan PySide6.
  3. Membuat pengaturan /etc/amr/robot.env dengan PIN staf Kiosk acak yang ditampilkan sekali — catat.
  4. Memasang dua service: amr-agent dan amr-kiosk, menyala otomatis saat robot hidup.
